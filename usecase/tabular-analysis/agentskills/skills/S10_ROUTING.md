# S10_ROUTING: タスク分解・依存・順序

## やること手順
1. `work/queue.json` を読み、依存が満たされたタスクだけを選ぶ
2. タスクMDの Scope/Acceptance/Verification を読み、実装が「何を満たせばDONEか」を先に固定
3. 追加作業が必要なら **同じタスク内にチェックリストを増やす**（新タスク乱立しない）
4. 詰まったら `Fix Plan` を書き、次ループで必ず解消

## 事故りやすい点
- 仕様を読まずに手を動かしてUI契約を破る
- 実装が中途半端のまま次タスクに進む

## DoD
- Task MD に `RESULT: DONE` と Verification 結果がある
- 次タスクが進めやすい `Next Improvements` が書かれている

## よくある差分
- 依存が足りない場合 → 先に依存タスクへ戻る（順序を壊さない）
